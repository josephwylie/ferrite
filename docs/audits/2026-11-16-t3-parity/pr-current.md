## Current behavior and data rules

- Same-repository PR links open an explicit numbered thread Panel surface without replacing the conversation. Repository and requested number are checked; wrong-number answers become read failures. Other-repository links do not silently reuse the checkout's PR. The active PR surface wins over branch metadata.
- Every tab retains the title, author/avatar, update time, base ← head, changed-file count, additions and deletions. Scrolled Summary, Timeline and Code use the compact identity row (avatar and age, branches, counts) with the title beside the PR number; Guide stays expanded. Available values come from provider reads, not fixtures or local-diff guesses. GitHub supplies all six metadata fields. GitLab supplies identity/update and an exact uncapped file count; capped counts such as `1000+` and unavailable additions/deletions remain unknown. Azure supplies available author identity; unavailable update/counts remain unknown.
- `PrSnapshot` and `WirePr` now carry optional reviewers and labels. Absent means unavailable; a present empty list means none. GitHub requested reviewers are combined case-insensitively with latest submitted verdicts; dismissal supersedes an older approval. GitLab combines requested reviewers and approvals. Azure reads reviewer identities/votes. GitLab label strings have unknown color/description; Azure labels remain unavailable. Summary does not invent editing permissions or display inactive mutation controls.
- Summary now has reviewer/label rows and Description, Checks and Comments in one scroll. Description and Comments start open; Checks starts closed. An empty description has the source placeholder. Metadata uses 96px labels, 8px gaps, 24px minimum desktop rows and 12px type; sections use 16px horizontal padding and 12px header padding. See `panel/pull_request/summary.rs` and pinned `PullRequestSummaryTab.tsx:342,362,830`.
- Comments preserve provider IDs, bot identity, avatar URLs, review state including dismissal, file position, snippet and replies. Bot history is no longer discarded. Default Summary filtering hides bot chatter and resolved/dismissed conversations, retains bot verdicts and human replies to bot roots, pages ten recent conversations, and reverses the same recent page when ordering changes. The Comments section count includes loaded replies. Filters are shared within the view session; section/order/page state belongs to each requested PR. They are not persisted across app restarts.
- Code reads the requested **published GitHub PR**, independent of the local branch. It resolves merge base/head, verifies complete file pagination, obtains full pinned before/after blobs, preserves rename sources and fork head repository, and rejects revisions that changed during the read. Missing/binary/oversized content is reported, never synthesized as blank context. Refresh errors retain the last good diff. GitLab/Azure remote Code remains unsupported and reports that limitation. This is no longer excluded merely because the previous model lacked remote data.
- Code reuses existing file folding, wrap, whitespace filtering, test-file filtering and revision-bound viewed marks. Remote PRs have no local stage or open-checkout-file actions. Viewed marks are local to this view/session and are not GitHub's persisted viewed state.
- Ask prepares the current composer with the requested PR context and preserves its draft; it does not submit. Other existing Ferrite PR mutations still hand work to the agent. They are not equivalent to T3's provider-backed writes and must not be described as such.

## Boundaries that must remain explicit

Reviewer/label pickers, title/description/comment edits, reactions, provider-backed merge controls and checkout/worktree orchestration require capabilities, permissions and write/error state absent from Ferrite's current PR contract. They are real T3 differences, not automatically “out of scope” because they were previously missing. Under the original no-new-features constraint they need an explicit scope decision rather than inert lookalike buttons or agent prompts presented as equivalent writes. Head-bound Guide runs likewise need more than recognizing a comment prefix.

For the current Summary conversation, persistent filters, collapsed finished cards, reviewer verdict staleness/badges and author/comment host links still differ. They do not explain PR #309's empty reviewer/label/comment display and should not displace the three visible corrections above. Timeline remains a comment presentation rather than T3's complete opened/commit/review/merge event stream.

No exact-parity completion claim is supported yet. In addition to the remaining table items, action-required/cancelled check states are still normalized through the older provider model.
