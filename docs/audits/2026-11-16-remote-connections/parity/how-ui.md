## Flow
### Connections page
1. `ConnectionsSettings` selects `environments` versus `access`. Desktop environment view first renders “This app” and `LocalEnvironmentSetting`; then “Environments” with Add action in the section header.
2. `useEnvironments()` supplies entries; primary is excluded from saved list, desktop-local WSL entries excluded from ordinary listed rows. Therefore the local machine is not duplicated as a saved remote card.
3. Each `SavedBackendListRow` shows a machine glyph, label, transport + status + Routes + Permissions in a compact identity block, then switch and ellipsis at right. Disabled dims identity only, leaving controls usable.
4. Empty saved environments render “No saved remote environments” plus pairing guidance in the group. Cloud discovery can add remote rows. Linked environments/load balancing/PR routing sections follow; they are materially separate capabilities, not decoration to fake.
5. Add action opens `AddEnvironmentDialog` and clears route target. The Routes “add” path opens the same dialog with an expected environment ID and changes title/button/success wording to “Add route”.
### Remote link
1. Every fresh dialog opens Remote link selected. Fields are Host (`backend.example.com`) and Pairing code (`PAIRCODE`); helper says “Paste a full pairing URL here to fill both fields automatically.”
2. Every Host change passes through `parsePairingUrlFields`; hosted pairing URLs and direct credential-bearing URLs are split into origin/host and token. Submit also reparses a full URL.
3. `parseRemotePairingFields` trims and requires host and code; failures use “Enter a backend host.” / “Enter a pairing code.” Inline text is destructive 12 px and an error toast also appears.
4. `connectPairing({ host, pairingCode, expectedEnvironmentId? })` calls shared onboarding. It resolves base URLs, fetches server descriptor, validates expected identity before consuming one-time credential, bootstraps bearer session, and registers target/profile/token.
5. Success closes/reset form and shows “Backend added” (or “Route added”). The environment is saved and reconnects at startup. Registration does not implicitly mean all UI switches away to that machine.
### SSH
1. SSH card exists only when `window.desktopBridge` exists. Entering it refreshes discovery; retained discoveries remain visible during refresh. Source error clears when changing mode at the pinned commit (parent observed older installed behavior differs).
2. Discovery entries have alias, hostname, username, port, source. Already-saved SSH targets are filtered out; alias prefix matches sort ahead of substring matches. Known-host entries preserve ports using `[alias]:port` as selection value.
3. Input click opens suggestions. With initial discovery pending: “Loading hosts…”. With matches: scrollable rows with alias, resolved address when different, Cmd+1…9 shortcuts. With nonempty discovery but no matches: `No hosts match "...".`. No suggestions popup if there are genuinely no discoveries and no pending discovery.
4. Selecting a suggestion immediately sets alias, calls `desktopBridge.resolveSshHost(alias)`, overlays known-host port, fills username/port, and calls `connectSshEnvironment`; it does not merely fill and focus Username as current Ferrite does.
5. Keyboard: standard autocomplete movement/highlight/selection; first Escape while popup open is consumed by popup path; shortcuts pick one of first nine matches; Enter submits manual host only if no highlighted popup item and host nonempty; IME composition is explicitly excluded.
6. Manual parse accepts user@host, host:port, bracketed IPv6 and optional port; separate username/port override inline fields. Host required, port integer 1–65535.
7. `connectSshEnvironment({target,label:"",expectedEnvironmentId?})` calls `SshEnvironmentGateway.provision`, then stores an SSH profile and bearer credential under stable remote environment identity. Its result closes modal and displays “Environment connected”.
8. While adding, cards/fields/submit are disabled and button text is “Adding…”. Close and Escape remain supported. Session generation prevents late discovery resolution/error from mutating a different reopened form. Closing clears all fields and resets mode to Remote link. Source tests explicitly cover reopen and late-resolution handling.
9. Desktop SSH verification uses global queued modal `SshPasswordPromptDialog`, max-width 448 px, no top-right close, password/code prompt, remaining `m:ss`, response/cancel/expired states. It calls `desktopBridge.resolveSshPasswordPrompt(requestId,response|null)`. Native `setup::Attempt` verification can retain its real challenge behavior but needs compatible separate-modal presentation rather than inline form replacement.
### Native current flow and concrete seams
1. `edit_connection(None,window,cx)` selects Settings Connections, clears Settings search, allocates three `InputState`s, subscribes Enter to submit, loads `machine::hosts::candidates()` synchronously, and immediately focuses SSH Host.
2. `connection_form()` filters string candidates by substring, truncates to four, and emits `ConnectionForm::Editing`. `choose_host` only fills Host and focuses Username; this must change for parity.
3. `submit_connection()` parses `Machine::from_ssh_fields`, checks target duplication, starts `setup::Attempt`. `poll_connections()` / `connection_event()` update phase or challenge. Successful connection is persisted through `save_connections` before editor is removed.
4. `save_connections()` preserves unreadable-settings refusal and unsaved-files leaving guards, writes settings, notifies `cockpit.settings_changed`, and refreshes machine presentation.
5. `connection_settings()` currently creates This computer/Connected row and a Remote environments group with Add form as first row, then remote rows. This is the exact seam to create header action, empty state and compact rows.
6. Rendering should remain `cockpit` controller -> typed `ferrite-ui` presentation -> `ferrite-frame` drawing. Add mode/fields/dropdown selection/busy state belong in editor/controller; layout constants belong in local renderer or semantic tokens, not in transport/setup code.
7. Existing Settings render focus restoration explicitly calls `connection_holds_focus`; if Add becomes a native dialog use active-dialog mechanism, otherwise extend this focus ownership for popup and mode controls. A nested deferred overlay must use priority above Settings and consume backdrop presses; same-level Settings backdrop must not close both at once.

## Boundaries
- Native UI parity can reuse current `setup::Attempt`, auth questions, persistence guards, machine navigation and environment-specific settings RPC. Adding Remote link is not a visual-only edit: the current UI boundary and `Machine::from_ssh_fields` path only express SSH. It requires a real link/credential/transport path, not a mode card with disabled/fake behavior.
- T3 distinguishes environment identity from connection routes. Same machine over SSH and Remote link joins routes only when expected identity matches. Native target-string duplication and one-window selected-machine navigation are not equivalent. Coordinate with backend/routing exploration before defining parity complete.
- T3 environment list toggles connection enabled and deletes only local registration. It does not stop remote agents. Native safety guards around active filesystem edits should remain.
- Generic native `Combobox` is useful infrastructure, but default searchable popup is a semantic mismatch for editable-host autocomplete. Use inline `InputState` + an anchored `ListState`/custom popup controlled by editor, or add an intentionally small reusable editable-autocomplete primitive. Do not force arbitrary manual hosts to be list options or introduce a second popup search field.
- `Window::open_dialog` gives real focus/close semantics and existing Cockpit pump cooperation, but default stock dialog visuals are not automatically T3. Dedicated renderer can reproduce T3 geometry while consuming existing modal mechanics. Existing `sheet_head` has a ruled fixed-height header unlike T3's roomy title/description header.

## Non-Obvious Things
- Latest source title is “Environments” within `/settings/connections`, while the old native page heading “Connections” plus “This computer / Connected” and inline SSH form substantially differ.
- T3 add does not expose an explicit Cancel in its ordinary modal body. Close X/backdrop/Escape cancel. Native inline Cancel+Add is visibly different.
- Autocomplete selection starts connection immediately; stale resolution is session-guarded; exact host typed can still be a suggestion; list is not truncated to four.
- The fields use default size input with 30 px desktop element height, not T3 `sm` variant. Button is 32 px desktop. Label is “Username” / “Port”, not “(optional)” copy; placeholders convey defaults.
- SSH failure and remote failure deliberately render differently; changing mode clears parent error in pinned source.
- Verification is separately queued, not owned solely by whether Add modal happens to be mounted.
- T3 has actual route/permission/diagnosis expansions. Mimicking their words without operational counterparts would satisfy appearance while violating requested functional parity.
- Native saved screenshot inspected (`.../evidence/screenshots/1000x700/01-connections-empty-1000x700.png`) shows a settings-only crop at 1520x896 physical pixels. The path label is not the PNG dimensions. Compare logical viewport/device scale and crop boundaries before image diffing; parent should preserve complete-window captures and region metadata.
- Settings active modal and deferred popup layers must be reconciled. Simply moving existing form into a new div can leave Settings swallowing keys or autocomplete behind modal.
