# What actual T3 use changes about the Ferrite audit

Ferrite's central problem is incomplete everyday behavior across existing surfaces. The live T3 comparison strengthens that diagnosis: the important differences are correct destinations, preserved content, understandable state, scoped input, and recovery. Adding another button or component will not close those gaps.

This phase used real GPT-6.1 Sol and Claude Sonnet 5.5 conversations in the installed T3 app, including actual child agents and command output. Six source specialists reconciled the UI with implementation; the parent alone operated the app. The installed build is `0.1.10-nightly.20261111.4544`, commit `1264c206aee0dce805d6279809118bc091f29d2f`. The original comparison checkout is 746 commits newer. [Installed-source provenance](t3-installed-source-match.md).

This is an investigation, not a repair. The inventory now contains **177 findings**, including the subsequently identified floating-details composition gap, with evidence levels and uncertainty intact. Successful T3 checks neither add Ferrite bugs nor close them. [Inventory and interpretation](../README.md#tally-and-interpretation).

The [subsequent surface reconciliation](surface-reconciliation.md) corrects the mistaken browser-preview interpretation, joins the rendered-root inventory to the specialist maps, and strengthens the placement and coexistence requirements. Fresh native checks confirm main-child/parent navigation preserves the staged parent draft and selected file, the details card coexists with a loaded file, and the bottom terminal drawer coexists with that workspace. Those observations have a separate ledger and do not retroactively expand the older coverage snapshot.

## Visual defects are part of the repair, not optional decoration

**Floating details correction:** the compact box at the transcript's top right is a distinct Thread details surface. Ferrite places its related information in the large tool panel's Overview tab. The earlier audit only named T3's card in the checklist; `quality-correction-005` now records its independent access, responsive presentation and coexistence requirement. [Source and fresh native evidence](thread-details-card-correction.md).

**Agent placement correction:** T3 opens a provider child as its own main conversation; Ferrite's ordinary click confines it to a compact right-panel transcript. The primary repair should provide the full child-conversation destination, with a compact inspector only as an optional secondary view. The earlier panel-focused recommendation did not carry this observed difference through. [Exact scope and corrected acceptance](subagent-placement-correction.md).

The browser criticism is concrete: Ferrite stacks the app surface row, a generic Browser heading, another page-tab row and navigation controls. Its inset container and repeated hierarchy use space without making ownership clearer. During loading, removing Annotate and adding a status row changes geometry. A visual fix must simplify that structure and keep the location field and page origin stable; changing colors alone leaves the defect. [Native and saved evidence](visual-quality-correction.md).

The panel complaint is also concrete. Automatic tool widths overwrite a shared remembered width and make a sparse Overview dominate the conversation afterward. Test a small Overview, visit every larger surface, then return, hide/reopen and restart. Preserve the user's deliberate size separately from a surface's temporary minimum. [Measured reproduction](panel-runtime-correction.md).

The sidebar snap remains a requirement gap. The installed T3 zero default does not invalidate the user's request. Its source demonstrates how positive-duration motion coordinates sidebar gap and body position and retains panel exit content. The audit captured a closing intermediate frame at 400ms; it did not measure opening/right-panel interpolation, reversal or frame rate. [Exact motion boundary](t3-pr-live-source-match.md#t3pr-live-12-zero-default-and-an-actual-animated-sidebar-close-at-400ms).

Quote and attachment quality requires readable context, a real inspection path, obvious editing controls and independent removal. T3's live image thumbnail, full preview, retained draft, editable citation comment and source return provide working examples. Ferrite's cramped quote and clipped child prose are saved visual failures; actual Ferrite image-picker/drop behavior is still unverified. [Attachment evidence](attachment-runtime-correction.md), [Agent evidence](agent-live-correction.md).

## T3 is a reference, not an exemption from basic behavior

T3's chat link menu offers integrated opening, system-browser opening and Copy Link. Its generic webpage menu is more limited. Right-clicking a sidebar PR badge opened a thread menu. Ferrite still needs predictable link actions in each context; these T3 limitations do not excuse the reported Copy-only experience. [Browser source match](t3-browser-live-source-match.md), [PR context trace](t3-pr-live-source-match.md#t3pr-live-09-pr-menus-offer-explicit-destinations-right-click-scope-is-specific).

T3 also ignores several typed PR query qualifiers, excludes command-output rows from thread Find, and its local native embedded page `prompt()` produced an actual unsupported-operation console error. That Prompt result is scoped to the Electron guest path: the separate streamed browser implementation has its own Prompt input overlay. The audit records those limits instead of treating every T3 feature as complete. Its successful browser form and child-output checks remain valid independent observations. [Presentation and runtime distinctions](surface-reconciliation-browser.md).

## What remains unproved

The [coverage reconciliation](t3-live-coverage-reconciliation.md) accounts for 273 overlapping checklist IDs. These are not 273 unique features or 273 completed tests. It identifies bounded native checks, control inspection, version-dependent behavior, inconclusive interactions and unexercised variants. All 21 settings sections were inspected; their integrations were not all activated.

The significant remaining runtime gaps include Ferrite's intermittent scroll stability under real streaming/manual input; live CEF keyboard and pointer variants; full opening/closing/reversal motion; actual Ferrite image intake; reconnect/restart races; remote PR mutations; and disabled voice/device/sharing integrations. T3 Source-only newer features cannot be represented as behavior of the installed build. The earlier [52-journey Ferrite matrix](workflow-coverage-correction.md) remains the authority for Ferrite runtime coverage.

The repair program must use complete journeys as release gates: enter through the user's real affordance, act with real input, observe data or provider receipt, recover, navigate away and back, then close/reopen. Include visual states and focus in the same check. A passing handler test, visible button or successful T3 reference action is insufficient. [Repair sequence](../remediation.md).

## Closure and review

Both actual model roots were archived after their children completed. Browser/devtools/terminal/side-chat test surfaces were closed; changed preferences and local PR association were restored. T3 quit normally, the fixture server exited, its port refused connections, and bounded test processes were absent. The isolated fixture and recoverable archived conversations remain as evidence. [Cleanup manifest](../evidence/t3-live/cleanup.json).

An actual Sonnet 5.5 child reviewed eight named audit artifacts and raised eight useful flags. Those corrections and remaining limits are recorded in [the independent review](t3-live-independent-review.md). It did not review the original tool transcript or screenshot pixels; no full transcript or independent visual sign-off is claimed.
