# Motion, measured: Claude and Codex against Ferrite

Every number below comes from `mov/*.mp4`, decoded frame by frame with ffprobe pts. Times are seconds into each clip. Pixel boxes are screen px (1x, so px = pt). The recorder writes about 90 frames a second (one every 11 ms, with gaps of 22 to 56 ms under load). "One frame" therefore means the change finished within 11 to 22 ms. A small residual that decays over the next 100 to 200 ms after a snap is the H.264 encoder refining a large change, not an animation: in-region intensity holds flat from the first frame (`claude-menus` + menu, frames 771 to 792).

The click itself is not visible in a recording. "Delay" is measured from the trigger's hover or press state to the first changed frame, so it is an upper bound.

## Notes

**The pattern.** Both apps snap anything the operator opens or dismisses: menus, the tool group (Claude), the panel (Claude), thread content, and jumps. Animation is reserved for content arriving on its own: streamed text, the user's bubble and the approval card. Ferrite has this backwards in places. It animates every menu, the panel, the thread switch and jump-to-latest, yet streamed text inside a row snaps.

**Codex is the more animated app.** It eases its panel, its "Worked for" group and its effort popover on expo-out curves. Ferrite already carries that curve (`MOTION_EASE_OUT_EXPO`, theme.rs:2855). Wherever the two apps differ above, this doc picks Claude: it is the app Ferrite's shell follows, and each of its snaps also deletes a per-frame cost in Ferrite.

**Not recorded.** This set has no take of: queue strip appearance, sidebar collapse (⌘B), Claude thread switch, toasts, the scroll-to-bottom button's own show/hide, hover blends, or a Codex user bubble while at the bottom. motion.md's earlier Codex note ("the user bubble pins to the top with empty space below") came from a different recording and could not be re-checked; in `codex-send` the view was scrolled up. Treat the toast and hover items as code-only.

## motion.md's ranked list, checked

1. **Snap the menus; 100 ms fade for the model popover; remove the blank first frame and the 3-frame card wait.** *Confirmed and widened.* All four list menus snap both ways in both apps. The only Codex popover that animates is the effort slider, at about 75 ms with a slight scale and rise, not "100 ms fade plus blur, no scale". Ferrite has no surface like it, so set `MOTION_MENU_IN_MS` to 0 for every menu (theme.rs:2891) rather than special-casing one. The blank frame is real (menu.rs:823-826, 950). The 3-frame wait applies only to a trigger with no geometry yet (cockpit.rs:11816), so drop it from the list.
2. **Loop cadence.** *Confirmed in code, corrected on target.* `MOTION_BRAILLE_FRAME_MS` = 80 on the 33 ms grid (theme.rs:2929-2932) lands on 66/99 ms ticks; use 66 or 99. The outline braille face is still `AppleBraille-Outline6Dot` (components.rs:534); this can't be measured from these takes. New: both apps blink the caret hard at 500/500 ms, so Ferrite's 1.1 s soft blink (theme.rs:2944) should become a 1.0 s step. Claude's own working glyph steps at 33 ms, so the 30 fps grid itself is fine; the problem is only frame lengths that are not multiples of it.
3. **Fade the queue strip in over 100 ms and ease the composer height.** *Not supported.* Neither take shows the strip appearing. Claude removes it in one frame, and its composer height snaps (claude-send 2.077). Keep both snapped. Remove this item.
4. **Remove the thread-switch veil.** *Confirmed.* Codex lands content in one frame with no crossfade. Remove `Swap` and `card_veil` (cockpit.rs:5841-5848; motion.rs:400).
5. **Streaming: fade new words over about 300 ms ease-out, drop the 4 px rise, move the frame request out of row render.** *Confirmed for Claude (300–350 ms per chunk); corrected for Codex.* Codex's per-word fade is about 550–650 ms, not "78% at 310 ms". Target 300 ms ease-out. Extend: Codex snaps inline code chips in, and snaps unfinished fades at turn end. Ferrite should also land any fade still running when the turn completes. Apply the same 250 ms ease-out with no rise to the user's bubble.
6. **Measure the sidebar and panel slides.** *Measured for the panel.* Claude snaps the panel and never reflows the transcript. Codex slides it over about 220–300 ms on expo-out with a column re-centre. Recommend Claude's snap with a fixed column position. That makes the "freeze Pane layout during the slide" fix unnecessary. The sidebar (⌘B) was not recorded.
7. **Tool group expand: snapping recommended.** *Confirmed (Claude snaps).* Also snap the output folds (pane.rs:6335-6360) and the chevron (`MOTION_CHEVRON_MS`, theme.rs:2907), so every disclosure behaves alike. Codex animates them all, and that is the minority choice here.
8. **Kit toasts onto the toast tokens.** Not recorded. The code fact stands (motion.rs:66-74).
9. **One hover duration.** Not recorded. Code confirms four: 80 (theme.rs:2798), 100 (2800), 120 (2881) and 150 ms (2913).
10. **Fade the scroll-to-bottom button.** Not observed. New, measured: Codex's jump is instant, while Ferrite glides 300 ms (transcript.rs:1462-1476). Make it a snap. Optionally show "•••" in the button while a turn runs out of view.
11. **Delete the star spinner and fix stale rule docs.** *Confirmed.* `working_spinner` (components.rs:542) is drawn only by the gallery/test at components.rs:2585. Theme rule 8 (theme.rs:112-123) still names it and says "No dot pulses", which theme.rs:1659-1661 overrides for `working_dots`.

**Revised order:** (1) menus to 0 ms, without the blank frame; (2) remove the thread veil; (3) streaming per-run fade of 300 ms and the bubble fade of 250 ms, with no rise and one frame source; (4) snap the panel and keep the column fixed; (5) snap tool groups, folds and chevrons; (6) jump-to-latest becomes a snap; (7) caret becomes a hard 1 s blink, and loop frame lengths become multiples of 33 ms; (8) approval card gets a 150 ms fade; (9) delete the star spinner and fix rule 8; (10) toasts and hover, unchanged until recorded.
